CSV accents in Excel: inspect UTF-8 and make a marked copy

Short answer

Garbled accents can come from reading UTF-8 bytes with the wrong encoding. A UTF-8 byte-order mark can help Excel identify the encoding, and Microsoft also documents text/CSV import routes for unmarked files. This checker validates UTF-8, detects the mark and shows a Windows-1252 simulation. It does not diagnose every garbled file or predict every Excel import path.

Follow along and build it step by step. You add each file yourself, run each command, and see the real recorded result.

A small Python byte checker with 32 small fixture tests. Its optional --fix creates a new marked copy with exclusive creation. The original is read only. A separate setup writes one fictional CSV only in a new sample folder.

Common mistakes

  1. Assuming garbled accents prove a missing mark. Inspect the original bytes and import settings first. Invalid UTF-8 needs a different encoding diagnosis.
  2. Calling a marked file safe. A mark does not prove valid UTF-8 or correct CSV structure. This checker validates the body even when a mark is present.
  3. Overwriting existing work. Setup and output creation refuse existing paths. Keep originals and inspect a new copy before importing.
  4. Taking the simulation as an Excel recording. The simulated Windows-1252 decoding is one possible misreading, not a prediction of your import settings.

Frequently asked questions

What is the byte-order mark here?

The three bytes EF BB BF at the start of a UTF-8 file. Microsoft says a UTF-8 CSV saved with a BOM can be opened normally in Excel, and also documents text/CSV import routes for files without it.

Does this show what Excel will do?

No. It shows a Windows-1252 decoding simulation of one UTF-8 example line. Excel version, settings and import route can differ. No Excel application was recorded.

Does --fix convert another encoding?

No. It first validates UTF-8. Invalid data is refused, with or without a mark. For unmarked valid UTF-8 it prepends the mark to a new copy; an already marked file gets no extra copy.

Will it overwrite an old copy?

No. Exclusive creation refuses existing output files, directories and links. If another write error interrupts a new copy, inspect the new path for incomplete data before trying again.

Does valid UTF-8 mean valid CSV?

No. The tool does not parse CSV or check delimiters, quoting, formulas, record counts or content accuracy. It reads the chosen path and can follow a source file link. The report prints an example line, so avoid private data.
